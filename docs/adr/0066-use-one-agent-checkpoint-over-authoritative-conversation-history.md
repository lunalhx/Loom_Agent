# Use one AgentCheckpoint over authoritative Conversation History

Status: Accepted.

Conversation History—not the retired Conversation Ledger subsystem—is the append-only fact source for messages and durable Tool results, while `AgentCheckpoint` remains the sole checkpoint type and stores execution recovery state plus an exact history anchor. AgentCheckpoint may only anchor already-durable History; a valid matching Tool Result in a durable History tail remains authoritative when the latest checkpoint lags, so recovery does not turn it back into an Interrupted Tool Call. Session Working Memory is separate and AgentCheckpoint stores only the current Run's overlay: a normally completed root Run projects that overlay across Runs, while suspension retains it only in AgentCheckpoint and every other terminal outcome discards the projection without deleting History facts. `TaskCheckpoint` is removed, no `RunCheckpoint` synonym is introduced, and the existing AgentCheckpoint changes schema directly without compatibility readers; it no longer duplicates complete Conversation History or Session memory. A missing, corrupt, incompatible, or invalidly anchored latest checkpoint fails visibly and never triggers silent fallback to an older version.
