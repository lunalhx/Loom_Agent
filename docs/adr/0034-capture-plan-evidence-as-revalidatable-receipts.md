# Capture Plan Evidence as revalidatable receipts

Runtime captures each successful, complete Repository State observation as an Evidence Receipt produced by a trusted tool adapter before model-visible output is truncated or redacted. A receipt contains the tool semantics, normalized observation scope, state digest, completeness, source Run, and a deterministic revalidation rule; it does not attempt to record every file descriptor opened by the tool process. Structured tools provide semantic receipts: file content for `read_file`, complete directory entries for `list_files`, and normalized query plus the complete result for `search`, including a successful no-match result. Plan v1 does not authorize Shell or build execution. If read-only Shell is introduced later, an invocation without a dedicated Evidence Adapter conservatively records the entire Repository State, so any subsequent repository change invalidates it; only a dedicated adapter may narrow that scope. Failed, incomplete, or non-revalidatable observations do not contribute precise Plan Evidence. This avoids platform-specific system-call tracing and correctly represents negative searches and clipped output.
