# Enforce an unrelaxable built-in safety floor

Status: Accepted.

Runtime ships an unrelaxable Built-in Safety Floor expressed through the same `ALLOW`, `ASK`, and `DENY` Permission Rules: only fully parsed, valid, workspace-confined read forms receive built-in `ALLOW`; recognizable high-impact actions such as privileged system changes, destructive repository operations, external mutation, publication, deployment, download-then-execute, and Full Access reads of host credential resources require `ASK` even under an `ALLOW` default; recognizable catastrophic calls such as direct root or home deletion, filesystem formatting, raw block-device writes, fork bombs, shutdown, and reboot are denied. Host credential reads always use non-persistable per-call approval. Other calls fall through to the configured default action rather than receiving a speculative risk classification, and collaboration-mode and Execution Profile authorization still run first. This floor governs permission decisions, not system calls: sandboxed Execution Profiles provide the enforceable capability boundary, while Full Access cannot guarantee detection of equivalent behavior hidden inside a script, plugin, interpreter, or binary.
